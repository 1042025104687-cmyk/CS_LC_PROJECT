Key Milestones

I use the Waterfall Planning model in five phases from December 2025 to March 2026. Each phase has to be mostly complete before proceeding to the next.

1

Planning (Dec 2025)

I research existing systems and note what my system needs to do. The hardest part is deciding which features to include. I have to cut a lot of ideas.

2

Core Modules (Dec 2025 – Jan 2026)

I create the Tkinter interface with 7 tabs. I make a Controller class to separate main logic from the UI. I also add the Simulator with 7 preset scenarios for testing.

5

I write test files covering all modules using pytest. I run stress tests with extreme values and 30-day simulated trends. I finish my video evidence and portfolio-site writeup.

Problem Encountered

Micro:bit LED Not Displaying Wanted Feedback

During testing, I notice the Python application calculates risk levels correctly and logs them to the console and CSV file, but the micro:bit display remains blank. The visual feedback loop is broken — users cannot see the current risk level on the physical device itself, which defeats the purpose of having a portable warning indicator.

Debugging Process

I repetitively used print statements to debug each module and identify where the problem occurs. The serial connection works correctly (sensor data arrives at the Python app), but the micro:bit script is not listening for incoming commands after sending its data. I use a serial tool to verify that the Python application does send RISK:HIGH commands back, confirming the issue is on the micro:bit receiving side rather than the Python transmission.

The Solution

I redesign the micro:bit controller converting to MicroPython. I felt it would increase my productivity as block coding is more limited. The new script checks for incoming serial data after each sensor read using uart.any(). When it receives a RISK:level command, it updates the current risk level and displays the corresponding LED pattern and/or plays audio.

Overview

Model Explanation

The Wildfire Model is a model that predicts wildfire risk on a 0–100 scale using three sensor inputs. It's designed to meet the brief's requirements for disaster risk modelling, adaptive system, and also triggering alerts based on environmental conditions.

Inputs

Temperature

Source: micro:bit sensor, temperature (°C).

Light level

Source: micro:bit sensor, light sensor (0–255).

Wind speed

Source: simulated or configured value (km/h).

Processing & Algorithm

Pseudocode - Wildfire Risk Prediction
FUNCTION predict(temperature, light, wind_speed):
    # Step 1: Normalise inputs to 0-1 range
    norm_temp  = (temperature + 10) / 60    # range -10 to 50 → 0 to 1
    norm_light = light / 255                 # range 0 to 255 → 0 to 1
    norm_wind  = wind_speed / 50             # range 0 to 50 → 0 to 1

    # Step 2: Apply weighted combination (weights sum to 1.0)
    score = (0.45 × norm_temp + 0.35 × norm_light + 0.20 × norm_wind) × 100
    
    # Step 3: Clamp score to valid range
    score = CLAMP(score, 0, 100)
    
    # Step 4: Map to risk category
    IF score >= 75: RETURN "Extreme"
    IF score >= 50: RETURN "High"
    IF score >= 25: RETURN "Moderate"
    RETURN "Low"
Python - wildfire_model.py
def predict(self, temperature, light, wind_speed=None):
    """
    Calculate fire risk from three sensor inputs.
    Returns a score from 0 to 100 and a category (Low/Moderate/High/Extreme).
    """
    # If no wind data, use a default value
    if wind_speed is None or (isinstance(wind_speed, float) and math.isnan(wind_speed)):
        wind_speed = self.default_wind

    # Step 1: Scale each input from 0 to 1 (normalisation)
    norm_temp = self._normalise(temperature, self.temp_min, self.temp_max)   # e.g. 30°C → 0.67
    norm_light = self._normalise(light, self.light_min, self.light_max)      # e.g. 200 → 0.78
    norm_wind = self._normalise(wind_speed, self.wind_min, self.wind_max)    # e.g. 25 km/h → 0.50

    # Step 2: Multiply each normalised value by its weight, then sum
    # Weights: temp=0.45, light=0.35, wind=0.20 (must add to 1.0)
    # Multiply by 100 to get a score from 0 to 100
    raw_score = (self.w_temp * norm_temp + self.w_light * norm_light + self.w_wind * norm_wind) * 100.0

    # Step 3: Clamp the score between 0 and 100
    risk_score = self._clamp(round(raw_score, 1), 0.0, 100.0)

    # Step 4: Convert score to a category (Low, Moderate, High, Extreme)
    risk_category = self._categorise(risk_score)

    return {
        "risk_score": risk_score,
        "risk_category": risk_category,
        "prediction": f"{risk_category} Probability of Fire (score {risk_score:.0f}/100)",
    }

Outputs

risk_score

Value 0–100 displayed on the dashboard.

risk_category

Low (0–24), Moderate (25–49), High (50–74), Extreme (75–100).

When score ≥ 50, the system triggers an alert, communicates and triggers micro:bit prevention measures, then logs the event.
